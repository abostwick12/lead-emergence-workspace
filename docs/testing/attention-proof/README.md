The cue-card and Home captures are scrolled viewport views. Home shows its
heading and first cues; additional cards continue below the frame. The mobile
views emulate Pixel 7 in Chrome; this is not physical-device or Safari proof.

Visual review checked readable card padding, source/task distinction, dates,
reasons, original links, wrapping and Home presentation. Automated journeys
also check no horizontal overflow, exact-task focus and confirmed widget
hiding/restoration. Large cue counts reflect the scale fixture, not actual
client activity or independently verified urgency.

Remaining experience risks include dense long queues, redundant parent/task
cues, first-use prioritization and the mobile shared header's truncated greeting.
Representative human acceptance is still required; screenshot inspection is
not usability, accessibility certification or measured time-saved evidence.
